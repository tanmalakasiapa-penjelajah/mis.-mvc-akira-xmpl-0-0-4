--------------------------------------------------------------------------------
 A. KONVENSI PENULISAN (PENTING)
--------------------------------------------------------------------------------

  Nama database  : akira-xmpl-0-0-4
  Engine         : SQLite
  Stack          : .NET (ASP.NET Core, CQRS + JWT)
  Nama tabel     : meja_<nama>          (contoh: meja_toko, meja_log)
  Primary key    : <tabel>_code  (TEXT 255, selalu NOT NULL)
  Tipe data      : semua teks -> TEXT 255 | flag -> INTEGER 0/1
                   | nominal -> NUMERIC (yang dihitung & di-sort)
  Audit wajib    : softdeleted | createdat | updatedat  (SEMUA tabel)
  Relasi         : kolom *_code mengarah ke PRIMARY KEY tabel lain
  CATATAN FK     : skema TIDAK memakai constraint FOREIGN KEY SQLite.
                   Integritas relasi & anti data yatim DIJAGA di lapisan
                   aplikasi (port Write / handler), bukan oleh database.
  Format kode    : di-generate server-side ->
                   "yyyy/MM/dd/HH:mm:ss_<tabel>_<acak>" (maks 255 karakter).
                   Contoh: 2026/08/07/10:30:00_meja_toko_A1b2C3d4E5F6
  PK = internal  : TIDAK pernah ditampilkan di UI. Untuk join & preview
                   dikirim lewat query string (karena memuat "/" dan ":").
  Format tanggal : simpan ISO "yyyy-MM-dd HH:mm:ss" agar pengurutan
                   asc/desc tetap benar sebagai teks.
  Boolean SQLite : true/false disimpan INTEGER 0/1. Di dokumen ini ditulis
                   "INTEGER DEFAULT 0" pada versi query.

  INDEX:
  - Setiap kolom yang sering dipakai untuk filter/join/sort diberi index.
  - Kombinasi yang HARUS unik diberi UNIQUE INDEX (anti duplikat).
  - Index dikelola via migrasi EF Core, bukan edit manual DB.

|  keuangan_code        text 255  not null  primary key      |
|  pengguna_code        text 255  not null  -> meja_pengguna | di ui tampil pengguna_email
|  toko_code            text 255  not null  -> meja_toko     | di ui tampil toko_name
|  keuangan_nominal     numeric    not null                  |
|  keuangan_judul       text 255  not null                    |
|  keuangan_deskripsi   text 255  not null                    |
|  keuangan_status      text 255  not null                    |
|  keuangan_tempat      text 255  not null                    |
|  keuangan_waktucatat  text 255  not null                    |
|  keuangan_softdeleted integer    default 0                  |
|  keuangan_createdat   text 255  not null                    |
|  keuangan_updatedat   text 255  not null                    |
+-------------------------------------------------------------+
  INDEX  : pengguna_code, toko_code, keuangan_waktucatat
  KETERANGAN toko_code : penanda "toko pemilik" catatan keuangan.
  Dipakai untuk isolasi data per toko (lihat bagian H): user dari toko
  PLMOG hanya melihat/mengubah catatan dengan toko_code toko miliknya.
  ENUM   :
    keuangan_status : masuk | keluar | hilang | pindah
    keuangan_tempat : tunai | bank | ewallet | others

  ATURAN ARAH UANG:
    masuk   -> PLUS   (+) nominal ditambahkan
    keluar  -> MINUS  (-) nominal dikurangi
    hilang  -> MINUS  (-) nominal dikurangi
    pindah  -> NETRAL (0) nominal tidak berubah, hanya pindah tempat.

|  log_code             text 255  not null  primary key      |

+-------------------------------------------------------------+
  INDEX  : log_pelaku, log_createdat, log_mencatat
  KETERANGAN:
  - log_pelaku    : pengguna_code pelaku.
  - log_mencatat  : aksi, nilai: create | update | login | logout |
                    softdelete | restore | delete
                    (create & update ikut dicatat agar SEMUA aksi tulis

--------------------------------------------------------------------------------
 E. CONTOH QUERY (INNER JOIN)
--------------------------------------------------------------------------------

  CATATAN UMUM:
  - Query baca SELALU filter softdeleted = 0, kecuali halaman Trash.
  - Kolom relasi ditampilkan sebagai NAMA (via join), bukan kode.
  - Pagination : LIMIT <jumlah> OFFSET (<halaman> - 1) * <jumlah>.
  - Sort & search memakai nama kolom target/tabel asal, bukan hasil join.

E1. LIST BIODATA (join pengguna + toko + jabatan)

  SELECT
    b.biodata_code,
    p.pengguna_email,
    t.toko_name,
    j.jabatan_name,
    b.biodata_fullname,
    b.biodata_phone,
    b.biodata_createdat
  FROM meja_biodata AS b
  INNER JOIN meja_pengguna AS p ON b.pengguna_code = p.pengguna_code
  INNER JOIN meja_toko     AS t ON b.toko_code     = t.toko_code
  INNER JOIN meja_jabatan  AS j ON b.jabatan_code  = j.jabatan_code
  WHERE b.biodata_softdeleted = 0
  ORDER BY b.biodata_createdat DESC;

E2. LIST BIODATA + SEARCH + SORT + PAGINATION

  SELECT
    b.biodata_code,
    p.pengguna_email,
    t.toko_name,
    j.jabatan_name,
    b.biodata_fullname,
    b.biodata_phone
  FROM meja_biodata AS b
  INNER JOIN meja_pengguna AS p ON b.pengguna_code = p.pengguna_code
  INNER JOIN meja_toko     AS t ON b.toko_code     = t.toko_code
  INNER JOIN meja_jabatan  AS j ON b.jabatan_code  = j.jabatan_code
  WHERE b.biodata_softdeleted = 0
    AND (
          p.pengguna_email   LIKE '%<kata>%'
      OR  t.toko_name        LIKE '%<kata>%'
      OR  j.jabatan_name     LIKE '%<kata>%'
      OR  b.biodata_fullname LIKE '%<kata>%'
      OR  b.biodata_phone    LIKE '%<kata>%'
    )
  ORDER BY t.toko_name ASC
  LIMIT 25 OFFSET 0;

E3. LIST HAK AKSES (join pengguna + target)

  SELECT
    h.hakakses_code,
    p.pengguna_email,
    tg.target_name,
    h.hakakses_read,
    h.hakakses_create,
    h.hakakses_update,
    h.hakakses_delete,
    h.hakakses_login
  FROM meja_hakakses AS h
  INNER JOIN meja_pengguna AS p  ON h.pengguna_code = p.pengguna_code
  INNER JOIN meja_target    AS tg ON h.target_code   = tg.target_code
  WHERE h.hakakses_softdeleted = 0
    AND p.pengguna_email LIKE '%<email>%'
  ORDER BY p.pengguna_email ASC, tg.target_name ASC;

E4. LIST KEUANGAN (join pengguna + toko + filter status)

  SELECT
    k.keuangan_code,
    p.pengguna_email,
    t.toko_name,
    k.keuangan_nominal,
    k.keuangan_status,
    k.keuangan_tempat,
    k.keuangan_waktucatat,
    k.keuangan_judul
  FROM meja_keuangan AS k
  INNER JOIN meja_pengguna AS p ON k.pengguna_code = p.pengguna_code
  INNER JOIN meja_toko     AS t ON k.toko_code     = t.toko_code
  WHERE k.keuangan_softdeleted = 0
    AND k.keuangan_status = 'keluar'
    AND t.toko_name LIKE '%<nama toko>%'
  ORDER BY k.keuangan_waktucatat DESC;

E4b. LIST KEUANGAN PER TOKO (contoh isolasi data - user toko PLMOG)

  SELECT
    k.keuangan_code,
    p.pengguna_email,
    t.toko_name,
    k.keuangan_nominal,
    k.keuangan_status,
    k.keuangan_tempat,
    k.keuangan_waktucatat
  FROM meja_keuangan AS k
  INNER JOIN meja_pengguna AS p ON k.pengguna_code = p.pengguna_code
  INNER JOIN meja_toko     AS t ON k.toko_code     = t.toko_code
  WHERE k.keuangan_softdeleted = 0
    AND t.toko_name = 'pepper lunch mog'     -- hanya data toko sendiri
  ORDER BY k.keuangan_waktucatat DESC;

E5. SALDO KEUANGAN PER PENGGUNA
  (masuk + | keluar & hilang - | pindah netral 0)

  SELECT
    p.pengguna_code,
    p.pengguna_email,
    SUM(
      CASE
        WHEN k.keuangan_status = 'masuk'  THEN k.keuangan_nominal
        WHEN k.keuangan_status = 'keluar' THEN -k.keuangan_nominal
        WHEN k.keuangan_status = 'hilang' THEN -k.keuangan_nominal
        ELSE 0                                -- pindah = netral
      END
    ) AS saldo_total
  FROM meja_keuangan AS k
  INNER JOIN meja_pengguna AS p ON k.pengguna_code = p.pengguna_code
  WHERE k.keuangan_softdeleted = 0
  GROUP BY p.pengguna_code, p.pengguna_email
  ORDER BY saldo_total DESC;

E5b. SALDO KEUANGAN PER PENGGUNA PER TOKO (isolasi data)

  SELECT
    p.pengguna_code,
    p.pengguna_email,
    SUM(
      CASE
        WHEN k.keuangan_status = 'masuk'  THEN k.keuangan_nominal
        WHEN k.keuangan_status = 'keluar' THEN -k.keuangan_nominal
        WHEN k.keuangan_status = 'hilang' THEN -k.keuangan_nominal
        ELSE 0
      END
    ) AS saldo_total
  FROM meja_keuangan AS k
  INNER JOIN meja_pengguna AS p ON k.pengguna_code = p.pengguna_code
  WHERE k.keuangan_softdeleted = 0
    AND k.toko_code = '<toko_code_plmog>'     -- hanya data toko sendiri
  GROUP BY p.pengguna_code, p.pengguna_email
  ORDER BY saldo_total DESC;

E6. RINCIAN SALDO PER TEMPAT (tunai/bank/ewallet/others)

  SELECT
    k.keuangan_tempat,
    SUM(
      CASE
        WHEN k.keuangan_status = 'masuk'  THEN k.keuangan_nominal
        WHEN k.keuangan_status = 'keluar' THEN -k.keuangan_nominal
        WHEN k.keuangan_status = 'hilang' THEN -k.keuangan_nominal
        ELSE 0
      END
    ) AS saldo_per_tempat
  FROM meja_keuangan AS k
  INNER JOIN meja_pengguna AS p ON k.pengguna_code = p.pengguna_code
  WHERE k.keuangan_softdeleted = 0
    AND p.pengguna_code = '<pengguna_code>'
  GROUP BY k.keuangan_tempat
  ORDER BY saldo_per_tempat DESC;

E6b. RINCIAN SALDO PER TEMPAT PER TOKO (isolasi data)

  SELECT
    t.toko_name,
    k.keuangan_tempat,
    SUM(
      CASE
        WHEN k.keuangan_status = 'masuk'  THEN k.keuangan_nominal
        WHEN k.keuangan_status = 'keluar' THEN -k.keuangan_nominal
        WHEN k.keuangan_status = 'hilang' THEN -k.keuangan_nominal
        ELSE 0
      END
    ) AS saldo_per_tempat
  FROM meja_keuangan AS k
  INNER JOIN meja_toko AS t ON k.toko_code = t.toko_code
  WHERE k.keuangan_softdeleted = 0
    AND t.toko_name = 'kimukatsu mog'       -- hanya data toko sendiri
  GROUP BY t.toko_name, k.keuangan_tempat
  ORDER BY saldo_per_tempat DESC;

E7. LOG AUDIT (pelaku + filter) - MEMAKAI LEFT JOIN

  SELECT
    l.log_code,
    p.pengguna_email AS pelaku_email,   -- kosong jika pelaku tak dikenal
    l.log_mencatat,
    l.log_oldvalue,
    l.log_newvalue,
    l.log_target,
    l.log_createdat
  FROM meja_log AS l
  LEFT JOIN meja_pengguna AS p ON l.log_pelaku = p.pengguna_code
  WHERE l.log_softdeleted = 0
    AND l.log_createdat >= '<dari> 00:00:00'
    AND l.log_createdat <= '<sampai> 23:59:59'
  ORDER BY l.log_createdat DESC
  LIMIT 25 OFFSET 0;

  CATATAN: log memakai LEFT JOIN karena pelaku mungkin sudah tidak ada
  (akun dihapus permanen). Baris log TIDAK boleh hilang -> pakai LEFT.

E8. TRASH LIST (data softdeleted) - contoh meja_toko

  SELECT toko_code, toko_name, toko_createdat, toko_updatedat
  FROM meja_toko
  WHERE toko_softdeleted = 1
  ORDER BY toko_updatedat DESC;

CREATE TABLE meja_toko (
  toko_code           TEXT(255) NOT NULL PRIMARY KEY,
  toko_name           TEXT(255) NOT NULL,
  toko_address        TEXT(255) NOT NULL,
  toko_email          TEXT(255) NOT NULL,
  toko_phone          TEXT(255) NOT NULL,
  toko_softdeleted    INTEGER DEFAULT 0,
  toko_createdat      TEXT(255) NOT NULL,
  toko_updatedat      TEXT(255) NOT NULL
);

CREATE TABLE meja_pengguna (
  pengguna_code       TEXT(255) NOT NULL PRIMARY KEY,
  pengguna_email      TEXT(255) NOT NULL,
  pengguna_password   TEXT(255) NOT NULL,
  pengguna_nonaktif   INTEGER DEFAULT 0,
  pengguna_softdeleted INTEGER DEFAULT 0,
  pengguna_createdat  TEXT(255) NOT NULL,
  pengguna_updatedat  TEXT(255) NOT NULL
);
CREATE UNIQUE INDEX idx_pengguna_email ON meja_pengguna(pengguna_email);

CREATE TABLE meja_jabatan (
  jabatan_code        TEXT(255) NOT NULL PRIMARY KEY,
  jabatan_name        TEXT(255) NOT NULL,
  jabatan_softdeleted INTEGER DEFAULT 0,
  jabatan_createdat   TEXT(255) NOT NULL,
  jabatan_updatedat   TEXT(255) NOT NULL
);

CREATE TABLE meja_biodata (
  biodata_code        TEXT(255) NOT NULL PRIMARY KEY,
  pengguna_code       TEXT(255) NOT NULL,
  toko_code           TEXT(255) NOT NULL,
  jabatan_code        TEXT(255) NOT NULL,
  biodata_fullname    TEXT(255) NOT NULL,
  biodata_born        TEXT(255) NOT NULL,
  biodata_address     TEXT(255) NOT NULL,
  biodata_phone       TEXT(255) NOT NULL,
  biodata_softdeleted INTEGER DEFAULT 0,
  biodata_createdat   TEXT(255) NOT NULL,
  biodata_updatedat   TEXT(255) NOT NULL
);
CREATE UNIQUE INDEX idx_biodata_pengguna ON meja_biodata(pengguna_code);
CREATE INDEX idx_biodata_toko    ON meja_biodata(toko_code);
CREATE INDEX idx_biodata_jabatan ON meja_biodata(jabatan_code);

CREATE TABLE meja_target (
  target_code         TEXT(255) NOT NULL PRIMARY KEY,
  target_name         TEXT(255) NOT NULL,
  target_keterangan   TEXT(255) NOT NULL DEFAULT '',
  target_softdeleted  INTEGER DEFAULT 0,
  target_createdat    TEXT(255) NOT NULL,
  target_updatedat    TEXT(255) NOT NULL
);

CREATE TABLE meja_hakakses (
  hakakses_code       TEXT(255) NOT NULL PRIMARY KEY,
  pengguna_code       TEXT(255) NOT NULL,
  target_code         TEXT(255) NOT NULL,
  hakakses_read       INTEGER DEFAULT 0,
  hakakses_create     INTEGER DEFAULT 0,
  hakakses_update     INTEGER DEFAULT 0,
  hakakses_delete     INTEGER DEFAULT 0,
  hakakses_login      INTEGER DEFAULT 0,
  hakakses_softdeleted INTEGER DEFAULT 0,
  hakakses_createdat  TEXT(255) NOT NULL,
  hakakses_updatedat  TEXT(255) NOT NULL
);
CREATE UNIQUE INDEX idx_hakakses_pengguna_target ON meja_hakakses(pengguna_code, target_code);
CREATE INDEX idx_hakakses_target ON meja_hakakses(target_code);

CREATE TABLE meja_keuangan (
  keuangan_code       TEXT(255) NOT NULL PRIMARY KEY,
  pengguna_code       TEXT(255) NOT NULL,
  toko_code           TEXT(255) NOT NULL,

--------------------------------------------------------------------------------
 H. ATURAN ISOLASI DATA (SCOPED ACCESS)
--------------------------------------------------------------------------------

  Tujuan: setiap pengguna hanya bisa melihat & mengubah data milik
  TOKONYA SENDIRI dan milik DIRINYA SENDIRI.

  1. SUMBER TOKO PENGGUNA:
     Toko seorang pengguna ditentukan lewat meja_biodata:
     biodata.pengguna_code = pengguna AND biodata.toko_code = toko.
     (1 pengguna = 1 biodata = 1 toko, pengguna_code UNIQUE.)

  2. TARGET DATA & TOKO PEMILIK:
     Setiap record data yang "ber-toko" wajib mencatat toko pemiliknya:
       - meja_biodata    -> kolom toko_code
       - meja_keuangan   -> kolom toko_code (keputusan: tambah kolom)
     Record lain mengikuti pemiliknya lewat relasi (contoh: meja_log
     mengikuti pelaku, meja_hakakses mengikuti pengguna).

  3. ATURAN AKSES:
     - SUPERUSER (Kobo, jabatan developer, toko developer):
       bisa CRUD SEMUA data, semua toko, semua target.
     - PENGGUNA BIASA (jabatan admin/stockkeeper/kitchen/kasir):
       a. Hanya record yang toko_code-nya = toko miliknya, DAN
       b. Hanya record yang pengguna_code-nya = dirinya sendiri
          (untuk data pribadi seperti keuangan miliknya).
       Aturan (a) dan (b): boleh diakses jika SALAH SATU terpenuhi,
       keduanya dinilai per target. Orang KMMOG tidak bisa melihat/
       mengubah data PLMOG, begitu juga sebaliknya.

  4. IMPLEMENTASI DI QUERY:
     - Setiap query list/detail/trash Read WAJIB menyertakan filter
       toko_code (kecuali superuser). Contoh: E4b, E5b, E6b.
     - Setiap command Write WAJIB menolak (403) jika record target
       bukan milik tokonya (kecuali superuser).
     - OtoritasService memeriksa: (hak target) + (toko_code cocok).

  CONTOH FILTER UNTUK PENGGUNA BIASA (kasir PLMOG):

  SELECT
    k.keuangan_code,
    p.pengguna_email,
    t.toko_name,
    k.keuangan_nominal,
    k.keuangan_status,
    k.keuangan_tempat,
    k.keuangan_waktucatat
  FROM meja_keuangan AS k
  INNER JOIN meja_pengguna AS p ON k.pengguna_code = p.pengguna_code
  INNER JOIN meja_toko     AS t ON k.toko_code     = t.toko_code
  WHERE k.keuangan_softdeleted = 0
    AND k.toko_code = '<toko_plmog>'          -- milik toko sendiri
  ORDER BY k.keuangan_waktucatat DESC;

  5. TABEL GLOBAL (TIDAK BER-TOKO) - keputusan revisi v0.0.3:
     meja_toko, meja_jabatan, meja_target, meja_pengguna, meja_hakakses,
     meja_log TIDAK punya kolom toko_code -> TIDAK terscoped per toko.
     Aturan untuk pengguna biasa:
       a. BACA  : boleh melihat SEMUA record tabel global (data
                  referensi), asalkan punya hak baca pada target itu.
       b. TULIS : create/update/delete/softdelete/restore hanya boleh
                  jika punya hak akses pada target itu.
       c. MASTER SENSITIF : meja_toko, meja_jabatan, meja_target hanya
                  bisa diubah oleh SUPERUSER (Kobo). Pengguna biasa
                  TIDAK bisa mengubah daftar toko/jabatan/target meski
                  punya hak, karena bisa merusak data semua toko.
     Log & hakakses mengikuti pemiliknya (plan-0-0-1 C): meja_log ->
     pelaku, meja_hakakses -> pengguna. Detail tampilan menyesuaikan
     hak yang dibaca (user biasa tidak melihat baris hak user lain
     kecuali diberi hak baca).
